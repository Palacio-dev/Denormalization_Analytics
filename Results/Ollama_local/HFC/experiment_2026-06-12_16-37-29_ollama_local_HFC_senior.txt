# Phase 2 - Analytical Modeling Strategy

### Chosen Architecture: **Star Schema with Reference Data Absorption**

**Justification:**
The primary analytical workload involves aggregating specimen data (`tombos`) across multiple dimensions (Location, Taxonomy, Time, Organization).
1.  **Join Reduction:** The `tombos` table currently has ~20 foreign keys pointing to different dimension tables. A Star Schema consolidates these into a single central fact table (`tombos_facts`) with denormalized columns. This eliminates the need for deep join trees (e.g., `Tombos` -> `Especies` -> `Genero` -> `Familia` -> `Reino`).
2.  **Read Performance:** BI tools (Tableau, PowerBI, Looker) and large aggregations benefit immensely from flat fact tables. Deep joins in Postgres are expensive; a denormalized fact table allows `GROUP BY` operations on all dimension attributes in a single pass.
3.  **Reference Data Absorption:** Small lookup tables like `tipos`, `tipos_usuarios`, `configuracao`, and `fase_sucessional` are absorbed into the fact tables to avoid joining against a central dimension table for these attributes.
4.  **Data Marts:** While a full data mart architecture (separate schemas per domain) is possible, given the interconnected nature of the biological and logistical data, a single unified Star Schema is more appropriate for cross-domain analysis (e.g., "Specimens in Brazil collected by collectors in São Paulo").
