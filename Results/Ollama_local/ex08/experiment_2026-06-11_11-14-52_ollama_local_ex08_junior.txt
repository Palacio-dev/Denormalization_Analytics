#### Section 1: Structural Analysis and Denormalization Plan

**1. Identification of Tables and Relationships:**
The schema consists of 10 tables with the following core relationships:
*   **Students (`aluno_ifb`)**: Central entity for student demographics.
*   **Courses (`curso_ifb`)**: Describes course structure. Linked to students via `matricula_ifb`.
*   **Enrollment (`matricula_ifb`)**: The bridge table linking Students, Courses, and Schools. Contains critical temporal and status data.
*   **Schools (`escola`)**: Linked to locations and performance metrics.
*   **Performance (`desempenho_enem`**): School-level ENEM performance metrics.
*   **Indicators (`indicadores_escolares`)**: School-level academic indicators (retention, approval rates).
*   **Participation (`participacao_enem`)**: School-level ENEM participation rates.
*   **Locations (`localizacao`)**: Geographic data for schools.
*   **Employment (`vinculo_empregaticio`)**: Links students to jobs, salaries, and locations.
*   **Remuneration (`remuneracao`)**: Salary data for employees.

**2. Tables to Merge (Denormalization Strategy):**
To optimize analytics queries (e.g., "Show all students who took ENEM, their school's approval rate, and their current salary"), we should reduce joins by merging entities that share a common key or are frequently accessed together in a single report.

*   **Merge `desempenho_enem`, `indicadores_escolares`, and `participacao_enem`**: These three tables are all keyed by `co_escola_educacenso` (or implicitly by year). Merging them into a single `escola_metrics` table eliminates the need to join three tables just to get school stats.
*   **Merge `escola` and `localizacao`**: Since `escola` only has a foreign key to `localizacao` and no other independent attributes, and location data is often queried alongside school data, merging them into `escola_geo` reduces join complexity.
*   **Merge `remuneracao` and `vinculo_empregaticio`**: These tables are tightly coupled. `vinculo_empregaticio` holds the employment type and duration, while `remuneracao` holds the salary values. Merging them into `emprego_aluno` creates a single record per employment instance, avoiding joins when reporting on student earnings.
*   **Keep `curso_ifb` separate**: Courses are often queried with filters on course type/nature which might be too granular to merge with the student demographic table without bloating it excessively. However, if the report is "Student X's courses," we can consider merging `curso_ifb` into `matricula_ifb` if the course details are rarely queried independently. *Decision: Keep `curso_ifb` distinct for maintainability, but merge its attributes into `matricula_ifb` if the report focuses purely on student course completion.* For this schema, we will merge `curso_ifb` into `matricula_ifb` to create a fully denormalized "Student-Course Record" table, as `co_curso` is already in `matricula_ifb`.
*   **Keep `aluno_ifb` separate**: Student demographics are fundamental and rarely overlap with other entities except through enrollment.

**3. Attribute-Level Changes:**
*   **New Table `escola_metrics`**: Columns from `desempenho_enem`, `indicadores_escolares`, and `participacao_enem`.
*   **New Table `escola_geo`**: Columns from `escola` and `localizacao`.
*   **New Table `emprego_aluno`**: Columns from `vinculo_empregaticio` and `remuneracao`.
*   **New Table `matricula_denormalizada`**: Columns from `matricula_ifb` + all columns from `curso_ifb`.

**4. Tradeoffs:**
*   **Storage Overhead**: The new schema will consume significantly more disk space due to data duplication (e.g., school name stored in multiple places, course details repeated for every enrollment).
*   **Write Performance**: Updates to specific fields (like a student's age or a course's description) will now require updating multiple rows in the denormalized tables, potentially slowing down DML operations.
*   **Data Freshness**: If source data changes frequently, the denormalized tables must be refreshed (ETL process) to reflect current state, whereas the original schema updates instantly.
