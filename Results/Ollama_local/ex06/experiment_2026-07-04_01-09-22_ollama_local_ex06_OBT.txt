Based on the **RISEN FRAMEWORK**, here is the analysis and design for the denormalized schema.

### <Steps>

#### 1. Analysis of the Provided SQL Creation Script
The input schema defines a hierarchical educational data model with the following entities:
*   **UF (State):** Top-level administrative division.
*   **MUNICIPIO (Municipality):** Child of UF, containing basic stats (IES count, Schools count, IEB/SAEB/ENADE averages).
*   **IDES (Higher Education Institutions):** Child of Municipality.
*   **ESCOLA (School):** Child of Municipality.
*   **CURSO (Course):** Child of IES.
*   **INDICATORS (Idea, Enade, Saeb):** Master tables containing raw metrics (Rendimentos, Notas Brutas/Padronizadas, Totais).
*   **ANO (Year):** The linking entity connecting Courses to specific Indicator years.

**Key Observations:**
*   **Redundancy:** The `MUNICIPIO` table holds aggregated data (`media_ideb`, `qtd_habitantes`), while `UF` holds population. `IES` and `ESCOLA` are structurally similar (both have `nome`, `rede`, `cod`), but `IES` has specific IDs (`sigla_ies`, `codigo_ies`) and `ESCOLA` does not (uses `cod_escola`).
*   **Join Complexity:** Queries typically involve joining `UF` -> `MUNICIPIO` -> `IES/ESCOLA` -> `CURSO` -> `ANO` -> `INDICATORS`.
*   **Data Types:** Mix of `INT`, `VARCHAR`, `REAL`, and `CHECK` constraints ensuring non-negative numbers.

#### 2. Analysis of 'Frequent Queries / Workload Context'
Since no specific queries were provided, we infer the heavy read workloads based on the domain (Educational Analytics):
1.  **State-Level Aggregation:** "Get total number of schools and IES in UF [X] for year [Y]". This requires joining `UF` -> `MUNICIPIO` -> `IES`/`ESCOLA` -> `ANO`.
2.  **School/IES Profile:** "List all schools in Municipality [X] with their network type and average IEB score". Requires joining `MUNICIPIO` -> `IES`/`ESCOLA` -> `ANO` -> `IDEB`.
3.  **Course Performance:** "Show average ENADE score for Course [Z] in Year [Y]". Requires deep joins through `CURSO` -> `ANO` -> `ENADE`.
4.  **Demographic Correlation:** "Compare population growth vs. IEB trends in UF [X]".

**Bottleneck:** The `ANO` table acts as a many-to-many bridge between `CURSO` and the indicator tables (`IDEB`, `ENADE`, `SAEB`). In a normalized model, calculating a specific year's average for a specific course requires multiple joins to traverse up to the municipality and down to the indicators, which is expensive on large datasets.

#### 3. Design of the New Denormalized Schema
Following the **ONE-BIG-TABLE MODEL** strategy:
*   **Single Table:** All data from `UF`, `MUNICIPIO`, `IES`, `ESCOLA`, `CURSO`, `ANO`, `IDEB`, `ENADE`, `SAEB` will be flattened into one massive table.
*   **Primary Key:** A composite key `(id_uf, id_municipio, id_ies, id_escola, id_curso, id_ano)` is selected as the Primary Key to uniquely identify every row. This covers the full path from State to Year.
*   **Foreign Keys:** Removed entirely. Relationships are implied by the presence of IDs.
*   **Attributes:**
    *   All columns from source tables are included.
    *   To avoid ambiguity (e.g., `nota_bruta_ce` exists in `ENADE` and `IDEB`), we prefix ambiguous columns with the source table name (e.g., `ideb_nota_bruta_ce`, `enade_nota_bruta_ce`).
    *   `id_uf` is added to the main table to link municipalities back to states, even though `MUNICIPIO` references `UF` directly.

CREATE TABLE EDUCATIONAL_DATA (
    -- Composite Primary Key to ensure uniqueness of Entity + Year
    id_uf INT NOT NULL,
    id_municipio INT NOT NULL,
    id_ies INT NOT NULL,
    id_escola INT NOT NULL,
    id_curso INT NOT NULL,
    id_ano INT NOT NULL,
    
    -- UF Attributes
    sigla_uf VARCHAR(2) NOT NULL,
    nome_uf VARCHAR(100) NOT NULL,
    qtd_habitantes INT CHECK (qtd_habitantes >= 0),
    
    -- MUNICIPIO Attributes
    nome_municipio VARCHAR(100) NOT NULL,
    qtd_ies INT CHECK (qtd_ies >= 0),
    qtd_escolas INT CHECK (qtd_escolas >= 0),
    media_ideb REAL,
    media_saeb REAL,
    media_enade REAL,
    total_participantes INT CHECK (total_participantes >= 0),
    
    -- IES Attributes
    nome_ies VARCHAR(100) NOT NULL,
    sigla_ies VARCHAR(20),
    codigo_ies INT NOT NULL,
    rede VARCHAR(100) NOT NULL,
    
    -- ESCOLA Attributes
    nome_escola VARCHAR(100) NOT NULL,
    cod_escola INTEGER NOT NULL,
    
    -- CURSO Attributes
    nome_curso VARCHAR(100) NOT NULL,
    
    -- ANO Attributes
    ano INT NOT NULL,
    
    -- IDEB Attributes (Prefixed to avoid ambiguity with ENADE/Saeb)
    ideb_rend_1 REAL,
    ideb_rend_2 REAL,
    ideb_rend_3 REAL,
    ideb_rend_4 REAL,
    ideb_ind_rend REAL,
    ideb_nota_ideb REAL,
    
    -- ENADE Attributes (Prefixed)
    enade_total_inscritos INT CHECK (enade_total_inscritos >= 0),
    enade_total_concluintes INT CHECK (enade_total_concluintes >= 0),
    enade_nota_bruta_ce REAL,
    enade_nota_padronizada_ce REAL,
    enade_nota_bruta_fg REAL,
    enade_nota_padronizada_fg REAL,
    enade_nota_enade_continua REAL,
    enade_nota_enade_faixa REAL,
    
    -- SAEB Attributes (Prefixed)
    saeb_nota_mat REAL,
    saeb_nota_port REAL,
    saeb_nota_padrao REAL,
    
    -- CONSTRAINTS
    PRIMARY KEY (id_uf, id_municipio, id_ies, id_escola, id_curso, id_ano),
    -- Note: No FOREIGN KEY constraints are applied per the ONE-BIG-TABLE MODEL requirement.
    -- Data integrity is maintained via the composite primary key and application logic.
);
