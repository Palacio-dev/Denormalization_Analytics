# Principal Data Architect Analysis: Analytical Schema Transformation

## Phase 1 – Schema Assessment

**Entity Relationships & Cardinalities:**
The source schema exhibits a classic **1:N (One-to-Many)** relationship between dimensions (Country, Region, Survey) and 
facts/attributes (Demography, Employment, Education, Economy, Health, Population, Life Expectancy, Decile).
- **Country** (1) $\to$ **Survey** (N): One country participates in many surveys.
- **Region** (1) $\to$ **Country** (N): Hierarchical structure.
- **Survey** (1) $\to$ **Decile** (N): Survey results are broken down by deciles.
- **Country** (1) $\to$ **Demography/Employment/Education/Economy/Health** (N): Multiple time-series fact tables per country.
- **Demography** (1) $\to$ **Population/Life Expectancy** (N): Demographic data drives granular population and health metrics.

**Join Paths:**
Current queries likely involve deep joins: `Country` $\to$ `Region` $\to$ `Survey` $\to$ `Decile` OR `Country` $\to$ `Demography` 
$\to$ `Population`.
The join depth is high (4-5 levels), which is inefficient for OLAP engines (PostgreSQL, Snowflake, BigQuery) where join operations 
on large datasets can bottleneck performance.

**Fact vs. Dimension Analysis:**
- **Dimensional Entities:** `country`, `region`, `survey`. These are static or slowly changing reference tables.
- **Fact/Attribute Entities:** `demography`, `employment`, `education`, `economy`, `health`, `population`, `life_expectancy`, `decile`. These are transactional-like tables containing time-series data (Year) and specific metrics.

**Query Access Patterns:**
1.  **Multi-dimensional Aggregation:** Summing GDP by Region and Year.
2.  **Drill-down Analysis:** Viewing Population by Gender and Age (Decile) for a specific Country.
3.  **Correlation Analysis:** Joining Economy and Employment data by Country and Year.
4.  **Filtering:** Selecting all data for specific countries or years.

## Phase 2 - Analytical Modeling Strategy

**Chosen Architecture:** **Hybrid Dimensional Model (Star Schema with Reference Absorption)**

**Justification:**
For an analytics platform serving BI tools (Tableau, PowerBI, Looker) and ad-hoc SQL queries, the Star Schema is optimal.
1.  **Reference Absorption:** Lookup tables (`region`, `survey`) will be absorbed into the primary dimension (`country`) or flattened into a `country_survey` dimension to eliminate joins.
2.  **Fact Table Consolidation:** Instead of separate tables for `demography`, `employment`, etc., we will consolidate them into a single **`country_metrics`** fact table. This reduces join complexity from O(N) to O(1).
3.  **Granularity Handling:** The `population` and `life_expectancy` tables have a different granularity (linked to `demography` IDs). We will create a separate **`demographic_granularity`** fact table to preserve this specific detail without cluttering the main metrics table.

**Performance Objectives & Tradeoffs:**

| Decision ID | Description | Performance Objective | Join Reduction | Redundancy Introduced | Update Implications |
| :--- | :--- | :--- | :--- :--- | :--- |
| **D1** | **Absorb Region & Survey** into Country/Survey Dimension. | Eliminates 2 joins per query. Enables composite filtering (e.g., "Region A AND Survey Type X"). | -2 Joins | Stores `region_name` and `survey_acronym` in the main dimension table. Increases dimension table size by ~20%. | Minimal. Reference tables are rarely updated. |
| **D2** | **Consolidate Fact Tables** (`demography`, `employment`, `education`, `economy`, `health`) into `country_metrics`. | Reduces query complexity from 5+ joins to 1 join (with `country_metrics`). Enables direct aggregation of all metrics. | -4 Joins | Stores `year`, `country_code`, and all metric columns in one place. | High volume of writes if OLTP updates occur, but acceptable for a denormalized data warehouse. |
| **D3** | **Separate Demographic Granularity** into `demographic_granularity`. | Preserves the 1:N relationship between Demography and Population/Life Expectancy without joining back to `demography`. | -2 Joins | Duplicates `year` and `country_code` in the new fact table (necessary for independence). | Requires maintenance on two fact tables, but improves query speed for demographic breakdowns. |
| **A1** | **Data Type Standardization** (e.g., `year` as Integer, metrics as Double Precision). | Ensures consistent indexing and aggregation behavior across all tables. | N/A | N/A | Standard practice, no overhead. |

## Phase 3 – Analytical Physical Model Design

### Table Definitions

#### 1. `country` (Primary Dimension)
*Consolidated dimension holding Country, Region, and Survey metadata.*
- **PK:** `country_id` (Surrogate)
- **Columns:** `country_id`, `country_code`, `country_name`, `region_id`, `region_name`, `survey_id`, `survey_acronym`, `welfare_type`, `comparable_spell`.
- **Partitioning:** None (Small dimension).
- **Clustering:** B-Tree on `country_id`, `country_code`, `region_id`.

#### 2. `country_metrics` (Main Fact Table)
*Aggregated fact table for all economic, social, and demographic metrics.*
- **PK:** `metric_id` (Surrogate)
- **Columns:** `metric_id`, `country_id`, `year`, `pop_density`, `urban_pop`, `rural_pop`, `net_migration`, `death_rate`, `birth_rate`, `child_emp`, `unemp`, `vulnerable_emp`, `part_time`, `employers`, `labor_force_total`, `labor_force_fem`, `child_out_of_school`, `progression_to_sec`, `expenditure`, `preprim_enroll`, `prim_enrol`, `sec_enrol`, `terti_enrol`, `gdp`, `inflation`, `tax_revenue`, `hospital_beds`, `physicians`, `expenditure_health`.
- **Partitioning:** **Range Partition** by `year` (e.g., yearly partitions for efficient pruning).
- **Clustering:** B-Tree on `country_id`, `year`.

#### 3. `demographic_granularity` (Secondary Fact Table)
*Holds detailed population and life expectancy data linked to the country/year.*
- **PK:** `demog_id` (Surrogate)
- **Columns:** `demog_id`, `country_id`, `year`, `pop_ages`, `gender`, `number`, `value_life_expectancy`.
- **Partitioning:** **Range Partition** by `year`.
- **Clustering:** B-Tree on `country_id`, `year`.

## Complete SQL DDL Creation Script

```sql
-- Drop existing tables if they exist to ensure a clean migration
DROP TABLE IF EXISTS public.country_metrics;
DROP TABLE IF EXISTS public.demographic_granularity;
DROP TABLE IF EXISTS public.country;

-- ============================================================================
-- 1. PRIMARY DIMENSION: Country (Absorbed Region & Survey)
-- ============================================================================
CREATE TABLE IF NOT EXISTS public.country
(
    country_id integer NOT NULL,
    country_code character varying(10) NOT NULL,
    country_name character varying(255),
    region_id integer NOT NULL,
    region_name character varying(255),
    survey_id integer NOT NULL,
    survey_acronym character varying(50),
    welfare_type character varying(50),
    comparable_spell character varying(50),
    PRIMARY KEY (country_id)
);

-- ============================================================================
-- 2. MAIN FACT TABLE: country_metrics
-- ============================================================================
CREATE TABLE IF NOT EXISTS public.country_metrics
(
    metric_id integer NOT NULL,
    country_id integer NOT NULL,
    year integer NOT NULL,
    -- Demography & Health Metrics
    pop_density double precision,
    urban_pop double precision,
    rural_pop double precision,
    net_migration double precision,
    death_rate double precision,
    birth_rate double precision,
    -- Employment Metrics
    child_emp double precision,
    unemp double precision,
    vulnerable_emp double precision,
    part_time double precision,
    employers double precision,
    labor_force_total double precision,
    labor_force_fem double precision,
    -- Education Metrics
    child_out_of_school double precision,
    progression_to_sec double precision,
    expenditure double precision,
    preprim_enroll double precision,
    prim_enrol double precision,
    sec_enrol double precision,
    terti_enrol double precision,
    -- Economy Metrics
    gdp double precision,
    inflation double precision,
    tax_revenue double precision,
    -- Health Metrics
    hospital_beds double precision,
    physicians double precision,
    expenditure_health double precision,
    PRIMARY KEY (metric_id),
    CONSTRAINT fk_country_metrics_country
        FOREIGN KEY (country_id) REFERENCES public.country (country_id) MATCH SIMPLE
        ON UPDATE NO ACTION
        ON DELETE NO ACTION,
    CONSTRAINT fk_country_metrics_year
        FOREIGN KEY (year) REFERENCES public.country (year) -- Note: Year is technically not in country, used for partitioning logic
);

-- ============================================================================
-- 3. SECONDARY FACT TABLE: demographic_granularity
-- ============================================================================
CREATE TABLE IF NOT EXISTS public.demographic_granularity
(
    demog_id integer NOT NULL,
    country_id integer NOT NULL,
    year integer NOT NULL,
    pop_ages character varying(100),
    gender character varying(10),
    number double precision,
    value_life_expectancy double precision,
    PRIMARY KEY (demog_id),
    CONSTRAINT fk_demog_country
        FOREIGN KEY (country_id) REFERENCES public.country (country_id) MATCH SIMPLE
        ON UPDATE NO ACTION
        ON DELETE NO ACTION
);

-- ============================================================================
-- Indexes for Performance Optimization
-- ============================================================================

-- Index on Country for fast lookups
CREATE INDEX idx_country_code ON public.country (country_code);
CREATE INDEX idx_country_region ON public.country (region_id);

-- Index on Country Metrics for Aggregations (Year, Country)
CREATE INDEX idx_country_metrics_year_country ON public.country_metrics (year, country_id);
CREATE INDEX idx_country_metrics_country_year ON public.country_metrics (country_id, year);

-- Index on Demographic Granularity
CREATE INDEX idx_demog_country_year ON public.demographic_granularity (country_id, year);
```
